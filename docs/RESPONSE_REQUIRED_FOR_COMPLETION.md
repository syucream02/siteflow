# 完了時の対応内容チェック（2026-11-11）

## 目的と判断

確認待ちの指摘で対応内容を空にすると、そのまま承認して完了できた。
「対応内容を記録したうえで完了する」というルールを守るため、
`lib/siteflow/domain.ts` の `changeStatus` に完了時の必須チェックを追加した。
画面に依存しない場所に置くことで、将来のAPIでも同じルールを利用できる。

## 今回の変更

- 完了への変更時、対応内容が空文字または空白だけならエラーにする。
- メッセージは「完了の前に対応内容を入力してください。」とする。
- 確認依頼時のチェック、対応内容ありの完了、差し戻しのルールは維持する。
- 画面の既存のエラー処理を利用する。UI・CI/CD設定は変更しない。
- 完了前の対応内容の編集や、空の内容の一時保存は禁止していない。

## 検証

- 追加テストは修正前に失敗し、問題を再現した。
- 修正後の業務ルールテストは8件すべて成功した。
- 追加テストでは空文字・半角空白・タブ・改行・全角空白を扱い、拒否した際に元の指摘と履歴が変わらないことを確認した。
- 既存テストで、対応内容ありの完了と差し戻しが成功することも確認した。
- `npm.cmd ci` でロックファイル通りに既存の依存ライブラリを復元した。依存の追加やロックファイルの変更はない。
- `npx.cmd tsc --noEmit --incremental false`：成功。
- `npm.cmd run build`：成功。Vinextのルート自動分類には `Unknown` 表示がある。
- ブラウザーでの操作確認は未実施。

## 学習のポイント

`target === 'done' && !issue.response.trim()` は、
「変更先が完了、かつ対応内容から前後の空白を除くと空」という条件。
`throw new Error(...)` で処理を止めるので、完了の状態や履歴を作る前に拒否できる。

読む順番は `changeStatus`、次に `tests/domain.test.mjs` の追加テスト。
次の練習は、画面で確認待ちの指摘を開き、対応内容を空にして承認し、
エラーが表示された後に内容を入力して完了できることを試す。

今回もメモリ上のデモであり、DB保存・認証は追加していない。
