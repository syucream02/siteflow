## 保存前の手順

2026-11-16追記：ローカルのCIにはアプリ/migrationの2イメージ送信とproduction承認記録を追加した。まだGitHubへ送っていない。mainへのpushは承認前でもGHCRへの保存を行い、本番切替の許可とは別になる。既存EC2のCDを承認後に停止し、production保護と新しい配信判定を確認するまでpushしない。`enabled`/`paused`/`incident.json`/`current.json`/`schema.json`等の実サーバー状態、秘密設定、取得トークンをリポジトリへ入れない。候補設定の例と実際の設定を区別する。

- 送信先・ブランチ・送信予定の差分を確認する。現在のci.ymlではmainへのpushがコンテナーイメージの送信につながるため、手元の保存とは区別する。
- 秘密情報、個人情報、実在の資料、環境ファイル、ログイン情報、DBダンプ、一時Chromeプロファイル、生成物を送信対象に含めない。画像内の内容も確認する。
- .gitignoreは過去や現在すでにGit管理されているファイルを消さない。除外ルールだけで判断せず実際の差分を読む。
- 設計案・未実装・実際の検証結果を区別する。古い結果を今回の成功として転記しない。
- 必要なソース・ロックファイル・マイグレーション・文書の不足、競合マーカー、意図しない設定変更を確認する。
- Gitの保護を弱めたり、履歴の作り直し・古い履歴のpush・強制pushで解決しない。秘密が履歴に入った場合は、認証情報の失効・再発行と影響確認が必要。

## 確認用コマンド

以下は読み取り専用。status --shortは簡潔な変更一覧、diff --statは未ステージ差分の規模、diff --cachedはステージ済み内容、diff --checkは未ステージ差分の空白問題や競合マーカー、--cached --checkはステージ済み差分の同じ確認。コミット・push・DB更新は行わない。

```sh
git status --short
git diff --stat
git diff --cached
git diff --check
git diff --cached --check
```

現在は前段階からの変更・未追跡ファイルが多数ある。diffだけでは未追跡ファイルの内容は読めないので、新規ファイルも読む。一括追加せず、今回送る対象を明確にして点検する。
