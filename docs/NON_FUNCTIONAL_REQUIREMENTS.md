# 非機能要件の台帳

目標は初期案。達成済みと未達成を混同しない。ユーザー数・データ量・予算が決まった段階で見直す。

| 項目 | 初期要件・測定条件 | 検証方法 | 現状 |
|---|---|---|---|
| 保守性 | UIに依存せず状態遷移を検証できる | domain.tsをNodeのテストで実行 | 実装済み |
| 入力の妥当性 | 空白件名、不正な日付、対応記録なしの確認依頼を拒否 | 境界値と業務ルールのテスト | クライアントのみ。APIでの再検証は未実装 |
| アクセシビリティ | キーボードで登録と詳細操作ができ、ラベル・フォーカス・エラー表示がある | Tab/Shift+Tab/Escapeの手動確認、後に自動検査 | 部品・スタイルに反映。網羅検証は今後 |
| スマホ対応 | 幅390pxで主要操作ができ、ページ全体に横スクロールがない | ブラウザ実機・画面幅変更 | レスポンシブ実装 |
| セキュリティ | 別企業の案件を取得・更新できない | 企業A/Bの認可統合テスト | 認証・API未実装 |
| 整合性 | 不正な状態遷移、同時更新による上書きを防ぐ | APIの競合テスト、DBトランザクション | 遷移のみ実装。競合対策は今後 |
| 性能 | 1万指摘/企業、20同時利用で一覧API p95 ≤ 500msを仮目標 | データ作成＋負荷テスト、条件・結果を保存 | 未計測。API追加時に再評価 |
| 可観測性 | エラーにrequestIdを付け、個人情報を除いたログから追跡できる | 意図的にエラーを起こしログで追跡 | 未実装 |
| 復旧 | DBバックアップ毎日、RPO 24時間・RTO 4時間を仮目標 | バックアップから別環境へ復元し計測 | 未実装 |
| 配信・品質 | 変更ごとに型検査・業務テスト・ビルドを実行 | GitHub Actionsの結果と失敗時の停止を確認 | ローカル検証。CIは今後 |

RPOは許容するデータ損失の時間、RTOは復旧までの許容時間。稼働率や復旧目標は、運用の費用も含めて決める。初版の履歴は編集可能なクライアントデータで、監査ログではない。
